# 見た目の決まり(雛形の考え方)

雛形の見た目は「紙と墨」。作り替えるときも、下の決まりを保つ。数値は雛形の初期値で、根拠のある基準ではなく目安。

## 基本

| 項目 | 決まり |
|---|---|
| 色 | 地・文字・罫線は落ち着いた無彩色寄り。差し色は1色だけ(`--accent`)。グラデーションを使わない |
| 文字 | 本文18px。入力欄は16px以上(iPhone は16px未満の入力欄に触れると画面が拡大する) |
| 押す所 | 高さ・幅とも44px以上 |
| 片手 | いちばん使う操作(入力・追加)を画面の下に置く |
| 区切り | 箱で囲むより、罫線と余白で区切る。角の丸みは小さく(雛形は3〜4px) |
| 明暗 | `prefers-color-scheme` で明るい画面と暗い画面の両方を持つ。色は `:root` の変数だけを切り替える |
| 言葉 | 画面の言葉は短い日本語。英語の決まり文句(Loading… など)を残さない |
| 隠す | `hidden` を付けて隠す要素に `display` を指定しても隠れるよう、`[hidden] { display: none !important; }` を消さない |

## 避ける見た目

どこにでもある自動生成らしさが出やすい形。使うなら理由を持つ。

- 角の大きく丸い箱を、同じ大きさでいくつも並べる
- 同じ形のカード3枚の横並び
- 紫から青へのグラデーション、光る影
- 見出しの頭の絵文字
- 大きな見出し+説明文+特徴3つ、という並び
- どの間隔も同じ余白(大事な区切りは広く、近いものは詰める)

## 待機画面(起動時の演出)

最初に目に入る画面なので、文字だけの「読み込み中」や、回る輪で済ませない。雛形は、罫線3本が順に引かれ、ペン先が止まり、名前が出て、紙がめくれるように上へ抜ける。

作り替えるときに守る条件(`js/app.js` の `runSplash`):

1. **読み込みが終わるまで本体を見せない。** 読み込み途中の画面(空の一覧など)を一瞬でも見せない。
2. **長くても数秒。** 雛形は下限1.3秒・上限3秒。上限に達したら必ず開く。
3. **押せば飛ばせる。** 飛ばしても、データの読み込みだけは待つ。
4. **動きを減らす設定(`prefers-reduced-motion`)のときは動かさない。** 雛形は、動きを止めて下限を0にしている。
5. 演出は CSS と SVG だけで作る(画像や外の部品を足すと、しまうファイルが増え、最初の表示が遅くなる)。
6. そのアプリの中身にちなんだ絵にする(雛形の罫線とペン先は、書きとめるアプリ向け)。

## 保存の層を分ける理由

`js/store.js` は、読み込み・一覧・追加・削除・書き出し・読み込み・全削除の関数だけを外に出し、どれも Promise を返す。画面側は保存先が何かを知らない。あとで保存先を IndexedDB やサーバーの API に替えるときは、`store.js` だけを書き換える。

localStorage は、文字列だけ・容量は数MB程度が目安(ブラウザによる。値は未確認)。写真や大量の記録を扱うなら、IndexedDB に替える。
